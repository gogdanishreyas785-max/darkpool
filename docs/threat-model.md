# DARKPOOL threat model

## Objectives and assets

The server is the trust boundary and official source of truth. Protect identity/session binding; membership; roles and Insider hint; Investigator clue; private chat; cash, shares, health, price, trades, votes and outcomes; timers; audit logs; bounded process resources. Keep match IDs isolated.

No claim is made against compromised host/root or all timing side channels.

## Boundaries and actors

Boundaries: local client to UNIX socket/parser; authenticated session to match router/state; player output to moderator/audit records; encrypted LAN client to TLS 1.3 adapter (port 4783); future remote client to deferred public Internet deployment.

Actors: buggy/malicious client, abusive local process, same-UID process, slow/disconnected client, authorized moderator, host administrator/root. Restrictive socket permissions and least privilege are required. Peer credentials identify OS account, not a distinct human if processes share UID; local auth policy needs approval.

## Threats, controls, evidence

| Threat | Controls | Planned evidence |
|---|---|---|
| Identity spoofing | Bind server identity to authenticated session; ignore sender ID claims. | Send as another player and forge state; reject with no state change. |
| Unauthorized actions | Central phase/role/membership validation; client cannot set authoritative fields. | Wrong role/phase/member and forged cash/share/role tests. |
| Cross-match leakage | Match-owned state, routing by authenticated membership, audience-filter private events. | Canary roles/chat/clue/trade/vote/timer/log across simultaneous matches. |
| Malformed/oversized input | Check lengths before allocation; schema allowlist; reject invalid version, truncation and text. | Negative suite/fuzz; no crash or corruption. |
| Flooding | Per-session authenticated requests are limited to 20/s with burst 40. All unauthenticated frames also consume a shared server-wide 32/s bucket with burst 512, so reconnecting does not reset the pre-authentication budget. Connection count and TLS/unassigned-session timeouts remain bounded. | Rate-limiter unit test; flood tests should verify responsive clients and record thresholds. The shared bucket is not per-source-IP throttling; distributed source churn still requires host/network firewall controls. |
| Slow consumer | Bounded output queue, backpressure/high-water policy, disconnect persistent slow readers. | Stop client reads; measure queue/RSS and other-client latency. |
| Local socket abuse | Least privilege, restrictive socket directory/mode, safe stale-socket cleanup. | Unauthorized local account cannot connect/read protected files. |
| Secret logging | Separate player output and privileged audit; redact roles/hints/clues. | Unique secret canaries absent from unauthorized output/logs. |
| Replay/duplicate | Request-ID policy and one action per phase. | Exact retry produces one mutation; conflicting ID rejected. |
| Weak or predictable credentials | Moderator, custom admission, and enrollment secrets must be 32–256 bytes; default match/resume tokens are 128-bit values from Linux `getrandom`. Entropy-source errors fail closed. | Unit tests inject entropy-provider failure/exception; coordinator tests reject short/oversized custom and enrollment secrets; server integration rejects short moderator credentials. Minimum length is not a measure of entropy for user-chosen values. |
| Credential timing and input-size abuse | Credential comparison does not early-return on length mismatch; inbound join tokens are capped at 256 bytes and resume tokens must be exactly 32 hex-token bytes before comparison. | Constant-time helper tests cover matching, mismatch, and differing lengths; coordinator tests reject malformed oversized resume tokens. |
| Worker credential disclosure | Worker launch uses an explicit minimal environment and shared-memory descriptors are close-on-exec; the worker refuses credential-bearing environment variables. | Worker integration seeds moderator, enrollment, and resume secrets in the parent environment and verifies worker startup through the sanitized exec path. |
| Join-token timing leakage | Protected-match join tokens are compared using the coordinator's constant-time comparison helper. | Coordinator tests exercise valid and invalid token admission; this is not a claim against every possible timing side channel. |
| Resume-token theft or replay | Each seat receives a cryptographically generated bearer resume token. A disconnected seat is reserved for five minutes; successful reconnection requires the matching seat to be disconnected and rotates the token, making the previous value unusable. | Reconnect regression verifies identity/role/seat restoration, token rotation, rejection of replay, and reservation expiry. Keep the token private and out of logs and source control. |
| Worker IPC misuse or failure | Worker IPC is local to the server host and uses fixed-size process-shared SPSC queues, process-shared synchronization, and eventfd wake-ups. The server validates requests and remains authoritative; worker output is advisory. Worker lifecycle handling fails pending requests and can restart a failed worker. Worker launch uses a minimal environment and close-on-exec descriptors; the child sets `no_new_privs`, disables dumpability, and disables core dumps. These are defense-in-depth controls, not a syscall sandbox or UID isolation. | Multi-process integration tests cover malformed/range-invalid input, queue bounds, startup failure, in-flight worker termination, cleanup, and recovery. |
| Network interception | Dedicated TLS 1.3 listener on port 4783 (AD-S9-01) with OpenSSL 3.x encryption, strict IP SAN matching, and dual verification (local CA and leaf fingerprint pinning; AD-S9-03). Moderator token and gameplay data encrypted inside TLS. Plaintext rejected on port 4783. | Automated TLS negative suite: reject plaintext, reject untrusted CA, reject mismatched IP SAN, reject expired cert, reject TLS 1.2, verify token encrypted. |
| Private LAN transport | Non-loopback plaintext TCP binding (port 4782) restricted to RFC 1918 private subnets; plaintext transport warning; OS firewall restriction required. Plaintext protocol does not protect against LAN eavesdropping; secure LAN play must use TLS on port 4783. | Strict IP validation rejects public/unassigned IPs and 0.0.0.0; integration tests enforce RFC 1918 bounds. |

## Residual risks

Same-UID peer credentials do not distinguish humans. POSIX MQ, shared-memory telemetry, and the server-worker channel are local same-host IPC mechanisms, not remote authentication boundaries; a process running with the service UID is within that local trust domain. The worker is not sandboxed, so host-level or same-UID compromise remains outside the protection offered by the IPC protocol. A stolen resume token can be used as a bearer credential until it is rotated, its seat is reclaimed, or its five-minute reservation expires. The legacy LAN transport on port 4782 is unencrypted plaintext: moderator tokens, player messages, and private roles/hints/clues traverse the network in plaintext and are readable by any host on the same physical or virtual broadcast domain if plaintext TCP is explicitly enabled. Port 4782 must be restricted strictly to a trusted private network (RFC 1918 subnets); exposing port 4782 to the public Internet or configuring router port forwarding for this plaintext service is strictly prohibited. Successful moderator authentication over plaintext TCP verifies credentials server-side but does not encrypt the connection or protect data in flight. While physical two-computer LAN acceptance for the 5-player baseline over plaintext port 4782 was completed on October 17, 2026, this test does not prove that TLS 1.3 was exercised manually across two computers. Encrypted, authenticated multi-machine transport is provided by S9 TLS 1.3 on dedicated port 4783, where automated integration (`darkpool_tls_integration_tests`) and load tests (`darkpool_load_tls_functional`) pass deterministically; physical two-computer manual exercise of TLS 1.3 remains a separate future validation step. Mutual TLS (mTLS) for players is deferred per AD-S9-02; players use server-authenticated TLS with anonymous sessions. Dynamic in-process certificate reload is deferred per AD-S9-04; rotation requires server restart. Public-Internet deployment is unsupported. Moderator visibility, log retention/integrity, and audit privacy still require separate policy decisions. The implemented reconnect policy is a five-minute per-seat reservation with single-use rotating resume tokens; it does not provide durable reconnect state across a server restart. Local caps reduce accidental/unprivileged abuse but cannot guarantee DOS resistance from privileged attackers. Advanced side-channel mitigation and sandboxing are deferred. Single-process design has no failover; a process loss ends active matches absent future persistence.
